# Forward

A small, offline-first **PWA** for moving forward on the areas of life that matter —
without trying to do everything at once.

- **Pages** are areas of life (Health, School, Money…). **Swipe left/right** between them,
  or tap the dots, or use the ← / → arrow keys.
- Each page holds one or more **roads** — the path you want to take.
- A road is an ordered list of **small goals**.
- When you reach a goal, **tap it and it turns green**. Tap it again if you didn't
  hold that level — it goes grey again. Nothing is locked in; it's your honest record.

Everything is stored **on your device** in `localStorage`. There is no account, no server,
and it keeps working with no connection once installed.

## "I opened `index.html` and it's blank!"

That's expected, not a bug. The root `index.html` is a **source** file — it points at
`src/main.tsx`, which is TypeScript + JSX that browsers can't run until Vite compiles it.
Opening it directly over `file://` gives an empty page, and browsers also refuse to load
`file://` *module scripts*, so `dist/index.html` is blank when double-clicked too.

Pick whichever you need:

| I want to… | Run | Then open |
| --- | --- | --- |
| develop, see changes as I edit | `npm run dev` | http://localhost:5173 |
| **a single file I can just double-click** | `npm run build:portable` | `Forward.html` |
| install it as a real PWA (offline, icon) | `npm run build && npm run preview` | the printed URL |

`npm run build:portable` produces a self-contained `Forward.html` (JS + CSS inlined) in the
project root. Chrome/Edge run it straight from disk and `localStorage` works there, so your
progress is kept. The only thing it can't do is register a service worker — for
install/offline use the `preview` route.

## Getting started

```bash
npm install
npm run dev        # http://localhost:5173
```

Other scripts:

```bash
npm run build           # type-check + production build into dist/
npm run build:portable  # one self-contained, double-clickable Forward.html
npm run preview         # serve the built app (use this to check the PWA/offline bits)
npm test                # run the unit + UI tests
npm run icons           # regenerate the PWA icons in public/icons/
```

## Installing it as an app

The service worker and install prompt only work over **HTTPS** (or `localhost`).

1. `npm run build && npm run preview`
2. Open the printed URL in Chrome/Edge/Safari.
3. Chrome/Edge: use the install icon in the address bar.
   iOS Safari: Share → *Add to Home Screen*.

It then launches full-screen, works offline, and gets the gradient arrow icon.

## Project layout

```
public/
  favicon.svg            hand-written SVG icon
  icons/                 PNG icons generated by scripts/generate-icons.mjs
scripts/
  generate-icons.mjs     dependency-free PNG generator (violet→cyan tile + arrow)
src/
  App.tsx                shell: top bar + swipe deck + "new page" modal
  index.css              all styling (dark theme, scroll-snap paging, green "reached" state)
  types.ts               Category → Road → Step
  store/
    reducer.ts           pure reducer + seed data (unit-tested)
    persist.ts           versioned localStorage load/save
    StoreContext.tsx     React context + useReducer provider
  components/
    SwipeDeck.tsx        native scroll-snap pager (dots + arrow keys)
    CategoryPage.tsx     one page: title, progress, its roads
    RoadCard.tsx         a road + its ordered goals + "x / y reached"
    StepRow.tsx          a goal you toggle green
    AddInline.tsx        "+ Add road" / "+ Add goal" inline field
    InlineEdit.tsx       tap-the-pencil rename
    Modal.tsx            bottom-sheet / centred dialog
    NewCategoryModal.tsx create a page (name + colour)
```

## Notes on the design

- **Swiping is native CSS `scroll-snap`**, so it keeps real touch momentum, costs no
  dependencies, and can't break in an offline service-worker environment.
- **State is a single reducer** over one `AppState`, persisted on every change. Wipe it
  with `localStorage.removeItem('forward.state.v1')` if you ever want a fresh seed.
- Icons are generated by a small script rather than checked in as opaque binaries you
  can't tweak — change the colours in `scripts/generate-icons.mjs` and re-run `npm run icons`.
